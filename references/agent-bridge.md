# 子 Agent 交接

主 Agent 从正在运行的 `scripts.run_repair` 读取每一行 JSON。`agent_request` 包含 `split` 或 `review`、输入 `request` 路径和输出 `response` 路径。分别以 `fork_turns=none` 启动一个切分 Agent 和一个复核 Agent；后续请求使用宿主的 follow-up 功能发给相应角色，包括其他小节和重试。两个角色必须是不同 Agent，同一时刻只处理一个请求；复用角色时历史上下文可能保留，因此每次只依据当前请求及其图片，不使用其他小节内容。每次只传请求路径、响应路径、本文件规则和 `nlm-course-slides/references/html-pagination-rules.md` 路径。Agent 写 JSON 到临时文件后重命名为指定响应路径，避免半写入。主 Agent 持续读取程序的新请求或最终报告，不按整个批次累计已处理请求数设上限。若宿主无法复用 Agent，释放已完成的 Agent 后再创建同角色的新 Agent；确实没有可用 Agent 时报告失败，不等待用户批准增加数量。

本修复流程的固定图数和原文完整覆盖优先于 `html-pagination-rules.md`：该参考中压缩、改写、省略总结、禁止收尾行动、封面处理或改变页数等规则不适用。原文已有的行动或反思内容必须保留，不能仅因为它出现在末页而判定不通过。

## split

请求包含本节原始 Markdown `source`、已按封面规则移除首行重复标题的 `body`、`cover_title`、旧分页 `old_pages`、按页顺序的 `images` 和固定图数 `count`。`baseline_pages` 是已发布页面，`previous_pages` 是上一版候选或已发布页面；结合 `user_feedback` 和 `review_feedback` 调整本节边界，用户只指出部分页面时保持 `baseline_pages` 中其余页面不变。观察图片，以旧分页为主要主题线索，对 `body` 按原有顺序选择连续文本片段；不得改写、补写或遗漏。旧稿漏掉的原文按主题并入相邻页，标题、段落、列表和表格尽量保持完整；图数与全文覆盖优先于结构偏好。封面固定为 `# <cover_title>`，正文不能重新插入这个已去重的首标题。

标题与内容的归属：新主题的大标题及引言应与其首个子标题及相关内容一起进入相应图片页，不要附在上一主题的末页；若图片本身对应独立的主题导读页，可让大标题和导读单独占页。表格后解释该表的段落应随表格结束，新子标题从其对应图片页开始。结合图片和全文判断，不能为满足规则遗漏或改写原文；用户对具体页面的明确要求优先。输出：

```json
{"pages": ["# 标题", "第一段原文", "第二段原文"]}
```

数组长度严格等于 `count`；封面后每页非空，依次连接覆盖完整 `body`。完成条件是响应文件存在且仅包含该小节结果。

## review

由复核 Agent 读取同一个小节的原文、旧分页、图片、用户反馈和候选 `pages`，逐页检查主题与边界，特别检查上级标题、首个子标题、表格及其结尾说明是否落在语义和图片匹配的页面；对于图片确实单独表达的主题导读页，允许上级标题独立成页。用户只要求调整部分页面时，确认其余已发布页面未改变。对于没有专属画面的遗漏原文，允许其按顺序并入相邻页。通过时输出 `{"approved": true}`；不通过时输出 `{"approved": false, "reason": "具体页码与边界问题"}`，便于切分 Agent 重试，不得改写候选页。完成条件是独立的响应文件存在；程序负责客观检查全文覆盖，语义复核不是对图片字节或语音质量的证明。
